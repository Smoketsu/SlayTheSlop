# 2026-10-11: Tooltips for statuses, intents, keywords, Gear and Brews (task 045)

Author: Agent B. Branch: `b/045-tooltips`, stacked on `b/057-fight-layout` (#120) with
`b/055-placeholder-sound` (#119) merged in. Lane: client (plus client tests). No core, data,
schema, project.godot or other contract change.

## What changed

- **`client/help/tooltip_text.gd`** (new): the one tooltip text table, `TOOLTIPS`, keyed by the
  GDD field name or core id (the `client/visual/icons.gd` keys: stats, every status id of
  `core/schema/README.md` "Status ids" with Broken Arm and Ick under `broken_arms` / `ick`, every
  intent kind, the skipped / target / seat markers, the Bro Meter, the three piles), plus the card
  keywords of `core/schema/card_def.gd` `KEYWORDS` and the Junk type. Sentences are written from
  GDD "Statuses", "Stats", "Card types and keywords", "Bro Meter" and "Turn flow"; where the GDD
  says nothing, nothing is said. No digit is typed: numbers are `{CONSTANT}` placeholders filled from
  `data/constants.json` through the ruleset (`{NAME}`, `{NAME:more}`, `{NAME:less}`, `{NAME:pct}`);
  an amount the GDD states without a constant is said in words, as in `how_to_play_text.gd`.
  Functions: `describe(ruleset, key)`, `all(ruleset)`, `fill(constants, template)`,
  `badge(name, value, description)`, `gear(ruleset, gear_id)`, `brew(ruleset, brew_id, at_baileys)`,
  `card(ruleset, definition)`, `option_tooltip(ruleset, option)`. Gear and Brew tooltips are the
  item's own `name` and `text` from its data file; at Baileys a Brew's tooltip is
  `RunText.shake_text()` ("Shake: <name> — <text>").
- **`client/visual/tooltip_view.gd`** (new): `make(text)` builds the wrapped tooltip control
  (an opaque panel, the first line in gold, wrapped at `MAX_WIDTH` pixels). Godot's own tooltip
  never wraps.
- **`client/visual/tip_button.gd`**, **`client/visual/tip_box.gd`** (new): a Button and an
  HBoxContainer whose `_make_custom_tooltip()` uses `tooltip_view.gd`.
- **`client/visual/stat_badge.gd`**: `show_value()` takes an optional last argument `description`;
  the tooltip is now `"<name>: <value>\n<description>"` (`TooltipText.badge()`), wrapped.
- **`client/visual/combatant_view.gd`**: new `tooltips` (key -> description) set by the fight
  screen; every badge, intent icon, marker and the HP bar add the key's description.
- **`client/visual/card_view.gd`**: wrapped tooltip; the fight screen sets a card face's
  `tooltip_text` to its keyword lines (`TooltipText.card()`, e.g. "Tapped: After play, ...").
- **`client/fight/fight_screen.gd`**: builds `_tooltips` (`TooltipText.all()`) on every redraw and
  hands it to the views; Hype orb, pile icons and Bro Meter (now a `tip_box.gd`) tooltips carry
  their description; buttons are `tip_button.gd`; a Brew button reads "Brew: <Brew name>" (was the
  Brew's id) with the Brew's data text as tooltip (`_brew_name()` added).
- **`client/run/run_screen.gd`**: the header line also lists the local Dude's Gear and Brews as
  small tags (`item_tags`) whose tooltips are the data text; while the Baileys screen is up the
  Brews are under "Shake:" with Shake tooltips (`at_baileys()`). Four existing undocumented
  variables got comments so the file passes the documentation lint.
- **`client/run/offer_screen.gd`**: every option button has a tooltip (`option_tooltip()`): a
  card's keyword lines, a Gear's data text, a Shake line at Baileys.
- **`client/ASSETS.md`**: the stale line saying the fight screen uses no icon files now points at
  `assets/placeholder/README.md` "Icons".
- **`tests/client/test_tooltips.gd`** (new) and **`tests/client/test_fight_layout.gd`** (057's
  exact tooltip checks now compare the first line, since the description follows on the second).

## Why

Task 045: a new player cannot tell what a status, an intent icon, a keyword, a Gear or a Brew does.
