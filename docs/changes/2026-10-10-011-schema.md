## Why

Task 011 (enemy intents, move choice and targeting) needs these three things:

- A data-driven way to script an enemy's moves. The GDD says Goblin Bouncer "alternates 8 Guard
  with a 9-damage hit". G11 (answered "accept") says scripted patterns are written as data and
  followed exactly, and the "never three times in a row" rule covers random choice only.
- A way to mark area attacks. The GDD says "Area attacks hit everyone", but a move has no field
  that says whether it hits one Dude or every Dude.
- A per-enemy move history, so the core can enforce "never repeats one three times in a row" and
  know where the enemy is in its pattern.

## Fields and constants added

| Name | Where | Type | Meaning |
| --- | --- | --- | --- |
| `pattern` | Enemy definition, optional | List of move ids | A scripted move order, at least one entry, each one a move id of this enemy. When it is present, the enemy ignores weights. Its n-th intent in a fight (counting from 0) is `pattern[n % size]`, so the order starts at the first entry and cycles. The pattern is followed exactly and the no-three rule does not apply to it (G11). It may name weight-0 moves. When it is absent, every intent is a weighted random choice. Set by the content lane. |
| `target` | Enemy move, optional | Text, one of `MOVE_TARGETS` | Who the move's effects that need a target are aimed at. `"dude"` is a single-target attack: 1 Dude, or `MULTI_TARGET_COUNT` different Dudes once the party has `MULTI_TARGET_PARTY_SIZE` players, chosen at random among Dudes who are not Passed Out. `"all_dudes"` is an area attack that hits every Dude who is not Passed Out. `"none"` means no Dude targets. When it is absent, a move with an op that needs a target (such as `damage`) counts as `"dude"`, and any other move as `"none"`. Set by the content lane. |
| `MOVE_TARGETS` | `enemy_def.gd` constant | Array of String | The allowed values of a move's `target`: `["dude", "all_dudes", "none"]`. Changes only through a contract PR. |
| `MOVE_OPTIONAL` | `enemy_def.gd` constant | Dictionary | The optional fields of a move and their types. For now it holds only `target`. Changes only through a contract PR. |
| `move_history` | Enemy state, required | List of move ids | The move id of every intent this enemy has chosen in this fight, oldest first. It gets one entry per `intent_set`, appended when the intent is chosen, so a move the enemy later skips still counts. It is `[]` until the enemy's first intent and grows by 1 per turn. Only the rules core changes it. |
| `SCHEMA_VERSION` | `run_state.gd` | int | Changed from 1 to 2. |

`MULTI_TARGET_COUNT` is a new tuning constant, added to `data/constants.json` in its own commit
(`docs/changes/2026-10-10-011-constants.md`).
