# 2026-10-10: Task 023 contract, the floor map shape

Author: Agent A. Branch: `a/023-contract` (split out of task 023's branch as its own contract PR). Lane: `run`. Needs approval from Agent B's person before it merges.

## What changed

- **`core/schema/run_state.gd`**: comments only. `node_index` and `map` now say what they hold
  (the map shape below). No field, type, default or `SCHEMA_VERSION` changed: `map` was already
  "shape owned by the run lane; `{}` until a map exists", and this fills that in.
- **`core/schema/README.md`**: a map node id row in "Ids", and a new section "The floor map".
- The ten map constants this shape refers to (`MAP_ROWS`, `MAP_*_NODES_PER_ROW`, `MAP_MAX_LINKS`,
  `NODE_SHARE_*`) are added in the constants contract PR (#24), so the two contract PRs never
  edit the same file. The table below is kept here for reference.

## Why

Task 023 generates floor maps. The client (task 020), the run flow (task 025) and `vote_node`
all need to know what `run_state.map` and `node_index` hold, and the G18 structure numbers and
the GDD node shares are tuning values, so they belong in the constants file.
Gap G18 ("accept") gives the structure; GDD "Node types" gives the shares.

## Fields whose meaning was filled in (`core/schema/run_state.gd`)

| Field | Meaning now |
| --- | --- |
| `node_index` | Index in `map.nodes` of the node the party is on. 0 is the entrance (`nodes[0]`, type `start`), before the first vote; range 0..`map.nodes.size() - 1`. 0 and meaningless while `map` is `{}`. |
| `map` | `{"floor": int, "nodes": Array}`, nodes ordered by row then column. |
| `map.floor` | The floor the map belongs to, 1 or more. |
| `map.nodes[].id` | `"r<row>c<column>"`, unique within the map. What `vote_node.node_id` names. |
| `map.nodes[].row` | 0 entrance, 1..`MAP_ROWS` the floor's rows, `MAP_ROWS + 1` the boss row. |
| `map.nodes[].column` | Order within the row, 0 = leftmost. |
| `map.nodes[].type` | `start`, `brawl`, `rival`, `side_quest`, `tailgate`, `baileys`, `loot` or `boss`. |
| `map.nodes[].links` | Ids of the next row's nodes this node leads to, in column order; `[]` for the boss. |

## Constants referred to (added in #24)

| Constant | Value | Unit | Meaning |
| --- | --- | --- | --- |
| `MAP_ROWS` | 7 | rows | Rows of nodes before the boss row (G18). Row 1 all Brawl, row `MAP_ROWS` all The Tailgate. 2 or more. |
| `MAP_MIN_NODES_PER_ROW` | 2 | nodes | Fewest nodes in one of rows 1..`MAP_ROWS` (G18). |
| `MAP_MAX_NODES_PER_ROW` | 4 | nodes | Most nodes in one of rows 1..`MAP_ROWS` (G18). |
| `MAP_MAX_LINKS` | 2 | links | Most next-row nodes one node links to (G18: 1 to 2). The minimum, 1, is structural. |
| `NODE_SHARE_BRAWL` | 45 | percent of a floor's nodes | Brawl share (GDD "Node types"). |
| `NODE_SHARE_RIVAL` | 10 | percent of a floor's nodes | Rival share. |
| `NODE_SHARE_SIDE_QUEST` | 20 | percent of a floor's nodes | Side Quest share. |
| `NODE_SHARE_TAILGATE` | 12 | percent of a floor's nodes | The Tailgate share. |
| `NODE_SHARE_BAILEYS` | 8 | percent of a floor's nodes | Baileys share. |
| `NODE_SHARE_LOOT` | 5 | percent of a floor's nodes | Loot share. |

Shares are whole percents (they total 100) rather than fractions, so the per-floor rounding is
exact integer math. "A floor's nodes" means rows 1..`MAP_ROWS`: the entrance and the boss are not
counted (the GDD gives the Boss as "1 per floor", outside the percentages).

No field, request, event or constant was renamed or removed.
