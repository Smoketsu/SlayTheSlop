# 2026-10-11: the fight screen picks a Dude for "ally" cards (Bro Hug); decision log G62

Author: Agent B. Branch: `b/ally-pick`. Lanes: client, tools (tests/client). No core, data or
contract changes.

## What changed

- **`client/fight/targeting.gd`**: three new functions decide an "ally" card's pick from the state
  instead of from `party_size` alone, matching what the core accepts since Agent A's #96 (task 035,
  G62): any Dude who is not Passed Out, the player's own included.
- **`client/fight/fight_screen.gd`**: `press_card()` uses them. When only one Dude can be targeted
  (solo, or every teammate Passed Out) an ally card is sent at once with `target_id` = the local
  player's id. When several can (co-op), the screen shows "Pick a Dude." and a click on a Dude's
  view sends that Dude's `player_id`. Clicks on a Passed Out Dude are ignored (their view was
  already disabled; `press_dude()` now also checks the state). A card waiting for a Dude ignores
  enemy clicks, and a card waiting for an enemy ignores Dude clicks. A `bad_target` reject re-arms
  the same kind of pick, as enemy targeting already did. Enemy targeting and the Bro Move flow are
  otherwise unchanged; `Targeting.mode()` and `auto_target()` are kept as they were (the Bro Move
  and existing tests use them).
- **`tests/client/test_ally_targeting.gd`**: new tests on the real core and the real data, plus an
  in-memory card shaped like Bro Hug (`tom_bro_hug` may not be in `data/` yet).
- **`docs/proposals/decision-log.md`**: one row added to "Other defaults accepted the same day" for
  G62, as built in #96. Nothing else changed.

## Why

Bro Hug (`tom_bro_hug`, target "ally", 7 Guard) is being added as data. The fight screen must send
it with a legal `target_id`: the core refuses `""` for an ally card since #96.

## Functions, variables, constants and parameters

Added in `client/fight/targeting.gd`:

- `static func pickable_dudes(state: Dictionary) -> Array[String]`: the player_ids of every Dude not
  Passed Out, in seat order. Parameter `state`: a run state with a fight in it.
- `static func mode_in_state(card: Dictionary, state: Dictionary) -> String`: `NONE`, `ENEMY` or
  `DUDE`; an "ally" card is `DUDE` only when more than one Dude is pickable. Parameters `card`: the
  card definition; `state`: a run state with a fight in it.
- `static func auto_target_in_state(card: Dictionary, player_id: String) -> String`: the local
  player's id for an "ally" card, otherwise `""`. Parameters `card`: the card definition;
  `player_id`: the local player.

Added in `client/fight/fight_screen.gd`:

- `var _pending_pick: String`: what `_pending_card` waits for, `Targeting.ENEMY` or
  `Targeting.DUDE`; `""` when no card waits.
- `func _card_def(card_uid: String) -> Dictionary`: the definition of a card copy in the local hand.
  Parameter `card_uid`: the card copy.
- `func _pick_for(card_uid: String) -> String`: `Targeting.mode_in_state()` for a card copy in the
  current state. Parameter `card_uid`: the card copy.

Changed in `client/fight/fight_screen.gd` (signatures unchanged):

- `press_card()`: uses `_pick_for()` and `Targeting.auto_target_in_state()`; sets `_pending_pick`.
- `press_enemy()`: does nothing for a card waiting for a Dude.
- `press_dude()`: does nothing unless a card waits for a Dude and the clicked Dude is pickable.
- `_send()`: a `bad_target` reject on `play_card` re-arms `_pending_card` and `_pending_pick` (only
  when the card still needs a pick).

Added in `tests/client/test_ally_targeting.gd`:

- Constants `SEED`, `FOES`, `HUG_ID`, `HUG_GUARD`, `HUG_CARD`; inner class `RecordingGateway` (vars
  `requests`, `reject_next`; `apply(ruleset, state, request)`); helpers `_rules()`,
  `_fight(rules, party_size)`, `_give_hug(state)`, `_screen(gateway, rules, state, player_id)`,
  `_free(screen)`, `_freeze(value)`.
- Tests: `test_solo_ally_card_targets_yourself`,
  `test_coop_ally_card_asks_and_sends_the_clicked_dude`, `test_coop_ally_card_can_pick_yourself`,
  `test_passed_out_dude_is_not_pickable`, `test_bad_target_rearms_the_dude_pick`,
  `test_enemy_card_ignores_dude_clicks`.

No field, constant or message was renamed or removed.
