# 2026-10-11: Turn and fight-result feedback: banners, the Ready pulse, animation speed (task 047)

Author: Agent B. Branch: `b/047-turn-feedback`, stacked on `b/045-tooltips` (which stacks on #120
and #119). Lane: client (plus client tests). No core, data, schema, project.godot or other
contract change; nothing new in the run state, a request or the run save.

## What changed

- **`client/visual/event_player.gd`**: `banners_for(events)` (pure) finds where a request's events
  change the fight's rhythm: "your_turn" at each `turn_started`, "enemy_turn" at the first enemy
  action of the turn (`enemy_acted`, `enemy_skipped`, `armless`), moved back over that enemy's
  Guard drop, and "victory" / "passed_out" at `fight_ended`. `play()` takes an optional
  `on_banner(kind, seconds)` callback and shows each banner after the events before it and before
  the ones after it, waiting `banner_seconds(kind)`. `banners_played` logs them.
- **`client/fight/fight_screen.gd`**: a banner band across the screen (`_build_banner()`,
  `_on_banner()`, `_hide_banner()`), also shown as "Your turn" when the screen opens on a player
  phase; `banner_log` and `banner_text` for tests; skipped animations still log banners. The result
  banner plays inside the request's playback, so `state_applied` (and the run screen's move to the
  rewards or the run-over view) comes after it. The Ready (end turn) button pulses
  (`ready_pulsing`, `_pulse()`) while `ready_should_pulse()`: the core would accept a probe
  `set_ready` and would refuse every card in hand (`card_playable()`, Core.validate()). No rule is
  worked out in the client. `_add_button()` now returns the button.
- **`client/fight/request_maker.gd`**: `probe_set_ready()`, a set_ready request that is never sent.
- **`client/fight/messages.gd`**: `BANNERS`, the banner words.
- **`client/settings/animation_speed.gd`** (new): the client setting `animation_speed` (normal,
  fast, instant): `speed(path)`, `set_speed(value, path)`, `seconds(base, path)`.
- **`client/settings/animation_settings.gd`** (new): the menu's Animations row (an OptionButton),
  built like the Sound row: `setup(path)`, `change_speed(speed)`, signal `save_failed(error)`.
- **`client/run/main_menu.gd`**: the Animations row under the Sound row (`animation_settings`).
  Two existing undocumented variables got comments for the documentation lint.
- **`client/run/run_screen.gd`**: each fight screen gets
  `AnimationSpeed.seconds(animation_seconds, settings_path)`; with the base at 0 (tests) it is 0
  whatever the setting.
- **`tests/client/test_turn_feedback.gd`** (new).

## Variables, fields, constants and settings

Added:

- Client setting key `animation_speed` (`AnimationSpeed.SPEED_KEY`), a String, one of `normal`,
  `fast`, `instant`; missing means `normal`. In `user://settings.cfg` only.
- `animation_speed.gd`: `SPEED_KEY`, `SPEEDS`, `FACTORS` (normal 1.0, fast 0.4, instant 0.0),
  `NAMES`, `DEFAULT_SPEED`.
- `animation_settings.gd`: `SPEED_LABEL`, signal `save_failed`, `settings_path`, `picker`,
  `_loading`.
- `event_player.gd`: `BANNERS`, `ENEMY_ACTION_EVENTS`, `TURN_BANNER_FACTOR` (3.0),
  `RESULT_BANNER_FACTOR` (6.0), `banners_played`; `play()` parameter `on_banner`.
- `fight_screen.gd`: `BANNER_BACK_COLOR`, `BANNER_FONT_SIZE`, `BANNER_LINE_FONT_SIZE`,
  `BANNER_CENTER`, `BANNER_COLORS`, `BANNER_FADE_SHARE`, `PULSE_COLOR`, `PULSE_SECONDS`,
  `banner_log`, `banner_text`, `ready_pulsing`, `_banner`, `_banner_title`, `_banner_line`,
  `_banner_tween`, `_ready_button`.
- `messages.gd`: `BANNERS`. `main_menu.gd`: `animation_settings`.

Renamed or removed: none.

## Why

Task 047: the fight had no rhythm: no sign of whose turn it is, no hint when nothing is left to
play, and the screen jumped to the rewards or the run-over view with no result banner.
