# 2026-10-10: Task 026, floor 1 encounters as data

## What changed
- `data/encounters/*.json` (13): The Basement's encounter groups from G19, one file per entry of Agent A's `ENCOUNTERS` fixture in `tests/run/fixtures/run_fixtures.gd`, in the `core/schema/encounter_def.gd` format, plus a short `text` note (not shown to players) naming the G19 or G61 source. Early Brawls: `basement_goblin_pledges`, `basement_goblin_bouncer`, `basement_skeleton_intern`, `basement_pledge_and_intern`. Brawls: `basement_keg_slime`, `basement_dorm_rats`, `basement_boo_zer`, `basement_kobold_ra`. Rivals: `basement_goblin_shot_caller`, `basement_hall_monitor_golem`, `basement_sewer_gator`. Boss: `basement_goblin_king_chad`. Loot: `basement_mimic_cooler`.
- `tests/data/test_encounter_data.gd`: every file against the schema and its fixture, `early` only on Brawls made of Pledges, a Bouncer or an Intern (G61), enemy ids resolve in the real ruleset with no `arrives_with` escort listed, and a fixed-seed run start on the real data that votes into the first Brawl.

## Why
Task 026. Without encounter files a run on the real data cannot leave the entrance: the first `vote_node` on a fight node is refused (`bad_target`).

`tools/data_files.gd` needed no change: `read_all()` already reads every folder under `data/`, and `core/ruleset/ruleset.gd` already knows `data/encounters/` (task 025). `tests/data/test_data_files.gd` `test_real_data_is_valid` builds the whole folder, so it now covers the encounter files without a change.

## Fields, variables and constants
None added to data or state formats; the encounter fields are task 025's (`id`, `floor`, `node`, `enemies`, optional `early`, `text`). Test constants in `tests/data/test_encounter_data.gd`: `FOLDER`, `SEED` (20261010), `EARLY_ENEMIES`, `RECORDED_ENCOUNTER` (`basement_pledge_and_intern`, the first Brawl's encounter for `SEED`).
