## Why, and the design choice for the node screens

The GDD has `vote_node` and `choose_reward` only (task 025: "Propose in a contract PR how Tailgate
(Nap or Lift), Baileys (buy, remove a card, leave) and Side Quest choices are sent: reuse
`choose_reward`, or add new types"). **Proposal: reuse `choose_reward` for every node choice.**

- Every open choice is an *offer* in the choosing player's `dude_state.offers`, with its options
  already worked out for that player (prices after Medical Card, the HP a Nap restores, which cards a
  Lift or removal may pick, whether a Side Quest option is offered). `reward_id` names the offer;
  `choice_index` picks an option, or -1 to skip a card reward or leave Baileys.
- The one thing an index cannot say is *which card* a Lift upgrades or Baileys removes, so
  `choose_reward` gets one optional field, `card_uid`. Old senders stay valid.
- Why not five new request types: the GDD's `choose_reward` already has `reward_id` ("which reward
  screen") and -1 to skip, which is exactly this; one type means one client screen model, one reject
  path and one place for co-op to keep choices per player. The screen shown comes from the state
  alone (task 020's check), so a save loaded mid-Baileys reopens Baileys.
- Offers live on the Dude, not the run, because rewards, Dolla Bills, Side Quest choices and Baileys
  are per player in co-op (GDD "Rules that change in co-op").

Other fields: `run_phase` (the GDD's state has no "where in the run" field; `combat`'s phase only
covers fights), `votes` (co-op voting: GDD "Map path"), `path` (G19's "first two Brawls" and the
client's drawn path), `encounter_id` (a fight's rewards follow what was fought, G19's Mimic),
`pending_statuses` (G25 asks for exactly this), `cards_removed` (GDD "75, rising by 25 each time").

Side Quest format: GDD has none (task 025 check). Exactly two options, `safe` and `dumb`, so the
dumb one is marked by shape and the core raises `dumb_options_taken` for it (task 016's check).
Chances are int percents in a `chance` operation rolled on the `side_quest` stream, never only in
text. Encounter format: G19 answers "which enemy groups" with a list, which is content, so it is data.

## Fields added, renamed or removed

### Run state (`run_state.gd`)

| Field / constant | Type | Meaning |
| --- | --- | --- |
| `SCHEMA_VERSION` | const | 7 -> 8 |
| `RUN_PHASES` | const | `"map"`, `"node"`, `"floor_end"`, `"lost"` |
| `run_phase` | text | One of `RUN_PHASES`; where the run is |
| `votes` | map player_id -> node id | Votes cast this map step, emptied when the party moves |
| `path` | list of node ids | Nodes moved onto this floor, in order (entrance not listed) |
| `encounter_id` | text | The encounter fought at the current node, `""` for none |

### Dude state (`dude_state.gd`)

| Field / constant | Type | Meaning |
| --- | --- | --- |
| `offers` | list of offers | Open choices on the current node, oldest first |
| `pending_statuses` | map status -> stacks | Statuses to start the next fight with (G25) |
| `cards_removed` | int, 0 or more | Baileys removals this run; sets the next removal price |
| `OFFER_SPEC` | const | Offer: `id` (`o` + number), `kind`, `def_id` (Side Quest id or `""`), `skippable`, `options` |
| `OFFER_KINDS` | const | `card`, `boss_gear`, `tailgate`, `baileys`, `side_quest` |
| `OPTION_SPEC` | const | Option: `kind`, `available` |
| `OPTION_OPTIONAL` | const | `card_id`, `gear_id`, `brew_id`, `price`, `amount`, `card_uids` |
| `OPTION_KINDS` | const | `card`, `gear`, `shake`, `remove`, `nap`, `lift`, `safe`, `dumb` |
| `check_offer()` | func | Checks one offer and its options |

### Requests (`request.gd`)

| Change | Meaning |
| --- | --- |
| `choose_reward.card_uid` (optional) | The card a `lift` or `remove` option acts on |
| Comment after `REJECT_REASONS` | Which existing codes the run requests use (below) |

**No new reject code.** The run requests reuse existing codes, because Agent B's
`tests/client/test_fight_screen.gd` requires a client message for every code in `REJECT_REASONS`
and the client lane is not Agent A's to edit:

| Code | Run-flow cases |
| --- | --- |
| `wrong_phase` | `vote_node` outside `"map"`; `choose_reward` outside `"node"` or naming no open offer; `pick_dude` (lobby not built) |
| `bad_target` | `vote_node` to a node that is not a link (or that the ruleset has no content for); `choose_reward` index out of range, -1 where not skippable, an unavailable option, a missing or wrong `card_uid` |
| `unplayable` | A Baileys price above the Dude's Dolla Bills; a Shake with every Brew slot full |

Proposed follow-up (one contract PR together with B's client messages): codes `bad_node`,
`unknown_reward`, `bad_choice`, `no_dolla_bills`, `no_slot` for those cases.

### Events (`event.gd`)

| Type | Fields | When |
| --- | --- | --- |
| `floor_started` | `floor` | A floor's map was made; the party is at its entrance |
| `vote_cast` | `player_id`, `node_id` | A player voted |
| `node_entered` | `node_id`, `node_type` | The party moved onto a node |
| `offer_opened` | `player_id`, `reward_id`, `kind` | A choice opened |
| `offer_closed` | `player_id`, `reward_id`, `choice_index` | A choice was answered, skipped or left |
| `item_bought` | `player_id`, `reward_id`, `choice_index`, `price` | A Baileys purchase or removal was paid |
| `card_upgraded` | `player_id`, `card_uid` | A card was Lifted or upgraded by a Side Quest |
| `brew_gained` | `player_id`, `brew_id`, `slot` | A Brew went into a slot outside a fight |
| `brew_not_kept` | `player_id`, `brew_id` | A Brew reward was lost to full slots |
| `side_quest_rolled` | `player_id`, `side_quest_id`, `percent`, `won` | A Side Quest chance was rolled |
| `pending_status_added` | `player_id`, `status`, `stacks` | A status waits for the next fight (G25) |
| `dude_revived` | `player_id`, `hp` | A Passed Out Dude woke after a won fight |
| `floor_ended` | `floor` | The boss is beaten and the Boss Gear picked |
| `run_ended` | `result` | The run is over (`"lost"`) |

`card_created.to` may now be `"deck"` (a card added outside a fight).

### Side Quest definition (`side_quest_def.gd`, new; `data/side_quests/`)

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | text | snake_case, equals the file name; never changes |
| `name` | text | Shown name |
| `text` | text | The prompt |
| `safe` / `dumb` | option | The two options; index 0 and 1 in the offer. `dumb` raises `dumb_options_taken` |
| option `label` | text | Button text ("Walk away" ...) |
| option `text` | text | What it does, exactly |
| option `effects` | list | Side Quest operations (header of the file; checked by `core/run/side_quests.gd`) |
| option `min_dolla_bills` | int, optional, 1 or more | Offered only at or above this many Dolla Bills (G23) |
| `OPTION_FIELDS` | const | `["safe", "dumb"]` |

### Encounter definition (`encounter_def.gd`, new; `data/encounters/`)

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | text | snake_case, equals the file name; never changes |
| `floor` | int, 1 or more | Floor it appears on |
| `node` | text | `brawl`, `rival`, `boss` or `loot` (`NODES`) |
| `enemies` | list of enemy ids | Left to right, at least one |
| `early` | bool, optional, brawl only | May be one of the floor's first `EARLY_BRAWL_COUNT` Brawls (G19) |
| `text` | text, optional | Notes; not shown to players |
| `NODES`, `EARLY_NODE` | const | The node kinds, and the one that may set `early` |

Nothing renamed or removed.
