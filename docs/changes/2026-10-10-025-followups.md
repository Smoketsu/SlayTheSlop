# 2026-10-10: Task 025 follow-ups from Agent B's review of #66

## What changed
- **Bug fix: the early-Brawl count when a vote is checked.** `core/run/encounters.gd` `brawls_before` and `candidates` take a new optional `entered` parameter (default `true`).
  - The draw on entering a node still leaves out `path`'s last entry, because that entry is the node just entered.
  - `node_flow.gd` `content_error` checks a voted node before the party moves onto it, so it now passes `false` and every `path` entry counts as an earlier Brawl. Before this fix, the vote check undercounted by one.
  - The actual draw was never affected: the early list is a subset of the full list, and only the "can this node be resolved" check used it.
- **New test:** assertions added to `tests/run/test_node_flow.gd` `test_early_brawls` for the vote-time count.
- **Stale docs fixed:**
  - `docs/tasks/025-run-flow.md` claimed `core/ops/README.md` was not touched.
  - `tests/run/fixtures/run_fixtures.gd`'s header said none of B's data had merged.
  - The README now names the right catalogue file, `core/run/side_quest_ops.gd`.

## Variables, fields and constants
- **`entered`** (parameter, bool, default `true`) on `Encounters.candidates` and `Encounters.brawls_before`. True when the party is already on the node in question. Only the run lane passes it.
- **`earlier`** (local, int) in `brawls_before`: how many `path` entries come before the node in question.
