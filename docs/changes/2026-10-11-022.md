# 2026-10-11: Bot players and a fixed-seed fight simulation (task 022)

Author: Agent B. Branch: `b/022-bot-sim`. Lane: tools (plus its tests). No core, data, client,
schema or contract change.

## What changed

- **`tools/bots/`** (new): bots that play one seat of a fight through `Core.apply()` only.
  - `bot_moves.gd`: the legal requests of a seat in a fixed canonical order (hand order with each
    card's targets, then Brew slots, then the Bro Move, then `set_ready` true), built from what a
    player sees and kept when `Core.validate()` accepts them; the bot generator's seed.
  - `random_bot.gd` (`random`): one legal request chosen uniformly with the bot's own generator.
  - `greedy_bot.gd` (`greedy`): most enemy HP removed, else most Guard, else the first playable
    card, else Ready; ties by canonical order. Scores a play by applying it to the current state
    (pure) and reading enemy HP and Guard from the result.
  - `bots.gd`: `make(name, run_seed, player_id)`.
- **`tools/sim/`** (new):
  - `fight_sim.gd`: `run(rules, options)` plays bots x party sizes x encounters x seeds and returns
    a deterministic text report (won / lost / stalled, win %, mean and max turns, mean damage taken
    per Dude and per seat, with a summary per bot and party size); argument parsing for the command.
  - `run_sim.gd`: the command (`--party-sizes`, `--seeds`, `--encounters` required; `--bots`,
    `--dudes`, `--turn-cap`, `--out` optional) on the real data.
- **`tools/README.md`** (new): what is in `tools/`, the bots, the simulation command and its
  arguments, how to re-record the test report.
- **`tests/tools/`** (new): `test_bots.gd`, `test_sim.gd`, `sim_fixtures.gd` (in-memory test
  content), `sim_expected_report.txt` (the recorded 5-seed report).
- **`docs/tasks/022-bot-player-and-balance-sim.md`**: checks ticked, log with the full run's
  numbers, status `in_review`.

## Why

GDD "Risks": balance across 1-4 players is to be measured by automated bot runs on the rules core.
Task 022 asks for the bots and a fixed-seed simulation that works for any party size.

## Fields, variables and constants

All added; nothing renamed or removed. Each is documented where it is defined.

- `tools/bots/bot_moves.gd`: constants `TARGET_ENEMY`, `TARGET_ALLY` (target kinds that name an
  enemy or a Dude), `PLAY_CARD`, `USE_BREW`, `USE_BRO_MOVE`, `SET_READY` (request type names);
  functions `request`, `next_seq`, `target_ids`, `legal_plays`, `ready_request`, `legal_requests`,
  `bot_seed`.
- `tools/bots/random_bot.gd`, `tools/bots/greedy_bot.gd`: constant `NAME` (the bot's name in the
  report and command); variable `generator` (the bot's own `RandomNumberGenerator`, seeded from the
  seed under test and the `player_id`); greedy functions `forecast_key`, `total_enemy_hp`,
  `total_guard`.
- `tools/bots/bots.gd`: constants `SCRIPTS` (name -> script), `NAMES` (sorted names).
- `tools/sim/fight_sim.gd`: constants `WON`, `LOST`, `STALLED` (outcomes), `DEFAULT_TURN_CAP` (50,
  a simulation setting, not balance), `REQUESTS_PER_SEAT_TURN` (200, loop guard), `ALL_ENCOUNTERS`
  ("all"), `ENEMY_JOIN` ("+"), `ALL_ROW` ("(all)"), `REPORT_TITLE`, `ARG_NAMES`, `REQUIRED_ARGS`.
  Report row fields: `bot`, `party_size`, `encounter`, `fights`, `won`, `lost`, `stalled`,
  `turns_total`, `turns_max`, `hp_lost` (per seat).
- `tests/tools/test_bots.gd`: constants `TOOL_DIRS`, `DOCUMENTED_DIRS`, `BANNED`, `RNG_ACCESS`,
  `STEP_LIMIT`. `tests/tools/test_sim.gd`: `EXPECTED_REPORT`, `FIXTURE_OPTIONS`, `REAL_OPTIONS`.
  `tests/tools/sim_fixtures.gd`: `CONSTANTS_FILE`, `CARDS`, `ENEMIES`, `DUDES`, `ENCOUNTERS`.
