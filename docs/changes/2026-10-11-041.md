# 2026-10-11: Card faces in hand (task 041)

Author: Agent B. Branch: `b/041-card-faces`. Lane: client (plus client tests). No core, data,
schema or contract change. No image, sound or font added (frames are flat `StyleBoxFlat` colours
drawn in code), so `assets/placeholder/README.md` and `client/ASSETS.md` are unchanged.

## What changed

- **`client/visual/card_view.gd`** (new): one card in hand drawn as a card face. A `Button`, so a
  click plays the card exactly as the old text button did. `render(definition, is_upgraded,
  can_play, fallback_name)` draws it from the copy's effective definition only (no card id in the
  file): name (with `RunText.UPGRADED_MARK` "+" and a green name when Lifted), Hype cost in a round
  badge in the top-left corner (`RunText.card_cost()`: a number, "X" for an X cost, "-" for an
  unplayable card), type by frame colour and a label, rarity (coloured), and the rules text. A card
  the core would refuse is dimmed (`DIM_COLOR`) but stays clickable, so the core's reject message
  still says why. `hover(on)` (wired to mouse enter/exit) lifts, straightens and enlarges the face to
  `HOVER_SCALE` on screen, keeping it inside the window; only the face moves, the click area does
  not. `drawn_text()` and the `shown_*` fields expose what it shows, for tests.
- **`client/visual/hand_view.gd`** (new): a `Container` that lays the faces out bottom-aligned and
  centred in a gentle fan (`FAN_DEGREES`, `FAN_DIP`). Side by side while they fit, evenly overlapped
  when they do not; cards shrink to the height the screen leaves (never below `MIN_SCALE`), so the
  Dudes and enemies above are never pushed or covered at rest. Static helpers `card_scale_for()`,
  `card_step()`, `tilt_room()`.
- **`client/fight/fight_screen.gd`**: the hand is a `HandView` of `CardView`s (`_add_card()`); the
  action buttons (Brews, Bro Move, Ready) moved into a column right of the hand, so a full hand fits
  1280x720 (and the default 1152x648 window). New `card_playable(card_uid)` asks the core
  (`Core.validate()`) whether a play of the copy would be accepted with some target the player could
  pick (`_probe_targets()`: the auto target, any enemy, or any pickable Dude); nothing about Hype,
  phase or playability is worked out in the client. Each of the layout containers now has its own
  comment.
- **`client/fight/request_maker.gd`**: `probe_play_card()` returns the play_card request
  `play_card()` would make next without raising the seq, for `card_playable()`; `_next()` and the
  new `_build()` share the request shape.
- **`client/fight/messages.gd`**: card face labels for every card type and rarity
  (`CARD_TYPES`, `CARD_RARITIES`, `card_type_name()`, `rarity_name()`).
- **`tests/client/test_card_faces.gd`** (new): faces of a common card, an upgraded card (alone and in
  the screen's hand after the core's Lift), a Junk card, an X-cost card and a copy with no
  definition; every type and rarity has a label and colour; dimming matches the core exactly on a
  10-card hand with 1 Hype (each card pressed on a fresh screen is applied iff its face was not
  dimmed); every card is dimmed outside the player phase; hovering every card of a frozen state
  sends nothing and changes nothing, then a press still plays; a full hand of 10 at 1280x720 stays
  inside the window and below every Dude and enemy view; hand spacing; no card id in the new
  scripts; the new and changed client scripts pass Agent A's documentation lint
  (`tests/core/test_documentation.gd` `lint()`, read only).
- **`tests/client/test_upgraded_cards.gd`**: `_hand_texts()` reads each card face's shown cost,
  name and text instead of a button's text (the hand no longer holds text buttons).

## Why

Task 041: cards in hand were plain text buttons; the player could not see type, rarity or whether a
card could be played, and long text was hard to read.

## Fields, variables and constants

- Constants: `CARD_SIZE` (face size at full scale, px), `COST_SIZE` (cost badge side, px),
