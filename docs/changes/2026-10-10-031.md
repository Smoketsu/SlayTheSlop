# 2026-10-10: Task 031, Power trigger depth guard

Author: Agent A. Branch: `claude/brave-cerf-to5qlg`, stacked on #50 (`a/019-goblin-king-chad`).
The constant itself is in its own contract PR (`docs/changes/2026-10-10-031-constants.md`).

## What changed

- `core/ops/ops.gd`: the op context carries `trigger_depth`, how deeply its effects are nested inside
  Power triggers. `fire_power_triggers_in_place` takes the depth of the effects that set the
  triggers off, fires nothing once it has reached `MAX_TRIGGER_DEPTH`, and runs each trigger's
  effects one level deeper. `make_context` starts at 0 from a ruleset and keeps the depth of an op
  context passed in its place (the on_draw effects of a draw inside a trigger stay in its chain).
- `core/ops/ops.gd`: a `draw` op's events are no longer reacted to a second time. The drawn cards'
  `on_draw` effects already fired their triggers inside the draw; the outer `run()` fired them
  again. This was a latent bug (no slice card shows it) that the new tests found.
- `core/combat/fight.gd`: `check_start` refuses a fight when `MAX_TRIGGER_DEPTH` is missing, not an
  int, or below 1.
- `core/ops/README.md`: the depth cap and the once-per-event rule, under "Powers".
- `docs/proposals/solo-slice-rule-gaps.md`: gap G53 (how deep may a trigger chain go). Answered "accept, 8" by steamjgrube in the
  review of #53 (decision log, #54).
- `tests/core/ops/test_trigger_depth.gd` (new, 10 tests) and `tests/core/ops/tom_fixtures.gd`
  (`ruleset()` takes optional extra cards).

## Why

Agent B's review of #50: a Power with `when: "enemy_buffed"` whose effects buff an enemy would set
itself off forever and hang the fight. A hard limit of 1 would break Reply Guy -> Gross Out ->
Friend Zone, so the cap is a tunable constant, suggested 8. The GDD is silent (G53).

## Added, renamed or removed

| Name | Where | Meaning |
| --- | --- | --- |
| `DEPTH_KEY` (`"trigger_depth"`) | `core/ops/ops.gd` const; op context key | The op context key with the trigger depth: an int, 0 or more. 0 for the effects of a card, move, Brew, Gear trigger or turn start; 1 inside a trigger they set off; and so on. A context without it counts as 0. Set by `make_context`, raised by `fire_power_triggers_in_place`. |
| `MAX_DEPTH_CONSTANT` (`"MAX_TRIGGER_DEPTH"`) | `core/ops/ops.gd` const | Name of the constant with the depth cap. |
| `NESTING_OPS` (`["draw"]`) | `core/ops/ops.gd` const | Ops that run further effects through `Ops.run()` themselves and emit no Power-relevant event of their own. `run()` does not react to their events again. |
| `check_constants(constants)` | `core/ops/ops.gd` func | Returns why `MAX_TRIGGER_DEPTH` is unusable (missing, not an int, below 1), or `""`. `constants`: `ruleset.constants`. |
| `depth` | parameter of `fire_power_triggers_in_place` | The trigger depth of the effects that set these triggers off. An int, 0 or more; defaults to 0 (turn start, tests). |
| `extra_cards` | parameter of `tests/core/ops/tom_fixtures.gd` `ruleset()` | More card definitions by id, added to the fixture ruleset. Empty by default. |
| `MAX_TRIGGER_DEPTH` | `data/constants.json` | See `2026-10-10-031-constants.md` (separate contract PR). |

No field was renamed or removed. No schema or event changed: a capped chain stops silently.
