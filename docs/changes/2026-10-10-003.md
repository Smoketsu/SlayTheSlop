# 2026-10-10: Task 003, named random streams

Author: Agent A. Branch: `a/003-random-streams`.

## What changed

- **`core/rng/rng.gd`** (new): the game's only source of randomness. One SplitMix64 stream per
  GDD stream name, each a single 64-bit int stored in `run_state.rng`, so a `var_to_bytes`
  snapshot resumes every stream exactly. Pure static functions; nothing is mutated.
- **`tests/core/rng/test_rng.gd`** (new): 13 tests: int overflow behaviour the generator relies on,
  the published SplitMix64 and FNV-1a vectors, no engine hash or engine RNG in `rng.gd`, recorded
  sequences for seed 12345 on every stream (computed independently in Python), stream
  independence, per-player streams, snapshot round trip mid-sequence, purity, range spread,
  weighted picks and shuffle.
- `docs/tasks/003-random-streams.md`: status `in_review`, checks ticked, log entry.

No shared contract changed. `run_state.rng` was already `map_of int` with the key format used here.

## Why

GDD "Random streams" and "Fields added for Ethan" require independent, seeded streams so that a
seed always gives the same map, one player's choices never change another's randomness, and a
reload cannot reroll an outcome. Writing the generator and the seed derivation out in integer
math means a Godot upgrade cannot change any stream; the fixed-seed test catches it if anything does.

## Algorithms

- Stream starting state: `mix64(run_seed ^ mix64(fnv1a64(key)))`, where `key` is the
  `run_state.rng` key (`"map"`, `"dice:p1"` ...). Depends only on the seed and the key.
- Step: `state += GOLDEN_GAMMA`, output `mix64(state)` (SplitMix64).
- `next_int` / `weighted_index` / `shuffle`: rejection sampling on the top 63 bits of each
  output, so every value is equally likely; Fisher–Yates from the last position down.

## Constants added (in `core/rng/rng.gd`, not tuning constants; never change them, as that changes every stream and breaks saves)

| Constant | Value | Meaning |
| --- | --- | --- |
| `SHARED_STREAMS` | `["map", "encounters", "combat_ai", "side_quest"]` | Streams shared by the party, keyed by bare name |
| `PLAYER_STREAMS` | `["rewards", "shuffle", "dice"]` | Streams each player has, keyed `<stream>:<player_id>` |
| `KEY_SEPARATOR` | `":"` | Separator in per-player keys (run_state contract) |
| `GOLDEN_GAMMA` | `0x9E3779B97F4A7C15` (as signed int) | SplitMix64 step added per draw |
| `MIX_MULT_1` | `0xBF58476D1CE4E5B9` (as signed int) | First SplitMix64 finalizer multiplier |
| `MIX_MULT_2` | `0x94D049BB133111EB` (as signed int) | Second SplitMix64 finalizer multiplier |
| `FNV_OFFSET` | `0xCBF29CE484222325` (as signed int) | FNV-1a 64 offset basis, for hashing stream keys |
| `FNV_PRIME` | `0x100000001B3` | FNV-1a 64 prime |
| `INT64_MAX` | `2^63 - 1` | Largest int; bound of the 63-bit values used for ranges |

## Functions added (all static, in `core/rng/rng.gd`)

Draw functions return `{"state": new run state, "value": result}`. The new state is a shallow copy
with a new `rng` Dictionary; other nested values are shared with the input.

| Function | Meaning |
| --- | --- |
| `key_for(stream, player_id = "")` | The `run_state.rng` key for a stream; asserts the name is known |
| `derive_stream_state(run_seed, key)` | A stream's starting state from the seed and its key |
| `create_streams(run_seed, player_ids)` | A new `rng` map with every shared and per-player stream |
| `with_new_streams(state)` | Copy of a run state with `rng` filled from its `run_seed` and Dudes' `player_id`s; used at run start |
| `next_u64(state, key)` | One raw 64-bit value |
| `next_int(state, key, lo, hi)` | A uniform int in `lo..hi` inclusive |
| `weighted_index(state, key, weights)` | An index chosen with probability weight / total (enemy move weights) |
| `shuffle(state, key, items)` | A Fisher–Yates shuffled copy of `items` |
| `mix64(z)` | SplitMix64 finalizer |
| `fnv1a64(text)` | FNV-1a 64 hash of the UTF-8 bytes, written out instead of `String.hash()` |
| `shift_right_logical(x, bits)` | Unsigned right shift, 1..63 bits |
| `_step`, `_bounded`, `_stream_state`, `_with_stream_state` | Private helpers, documented in the file |

No state fields, data fields or tuning constants were added, renamed or removed.

## Found along the way

- GDScript's `>>` refuses a negative operand ("Only positive operands are supported"), so a plain
  `>>` cannot be used for an unsigned shift. `shift_right_logical` clears the sign bit first.
- GDScript `+` and `*` on ints wrap modulo 2^64; `test_int_math_wraps_as_relied_on` proves it.
- Hex literals above `INT64_MAX` are avoided; the constants are signed decimals, hex in comments.
- Range checks are `assert()`, which runs only in debug builds (tests and the editor).
- Weighted picks over values taken from a Dictionary must sort the keys first.
