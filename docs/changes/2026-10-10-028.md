# 2026-10-10: Task 028, fight screen sprites, health bars, intents and event animation

## What changed
- Added `client/visual/sprites.gd`: looks up a Dude or enemy `def_id`'s placeholder art in
  `res://assets/placeholder/characters/<def_id>.png` (#81), with a `FALLBACKS` table (ids only;
  `foam_slime` borrows `keg_slime`, smaller and paler) and a generated generic box for any other id
  with no art, so missing art shows and never crashes.
- Added `client/visual/combatant_view.gd`: one Dude or enemy as a clickable `Button` holding its
  sprite, name, HP bar and text, Guard, statuses, details (Hype, Brews, piles; or arms and Ick) and,
  for an enemy, its intent. Drawn by `render()` from one fight model entry; its animation methods
  (`hit`, `guard_to`, `heal_to`, `die`, `pass_out`) change only how it looks.
- Added `client/visual/event_player.gd`: maps each event to an animation kind (`effect_for()`,
  pure) and plays a request's events in order on the views (`play()`, `play_one()`): damage flashes
  red, shakes and pops the HP lost; a fully blocked hit and a Guard gain flash blue; a heal flashes
  green; an enemy that dies, flees or splits fades out; a Dude who Passes Out greys and tips over;
  every other event only logs. With `seconds <= 0` everything is instant and nothing waits.
- `client/fight/fight_screen.gd`: Dudes on the left, enemies on the right as combatant views
  (clicking one calls `press_enemy` / `press_dude` as the old buttons did); an event log of the
  last `LOG_LINES` lines under them; `_send()` plays events through the event player, then redraws
  from the returned state. `drawn_text()` now skips empty text.
- `client/fight/fight_model.gd`: Dude and enemy entries also carry `def_id`, `hp_now` and `hp_max`.
- Added `client/visual/backgrounds.gd` (after merging `main` with #84's backgrounds): the room
  behind a fight is the first enemy, left to right, with a file `assets/placeholder/backgrounds/
  <def_id>.webp` (a boss room, such as `goblin_king_chad`); otherwise the floor's room from
  `FLOOR_ROOMS` (floor 1 -> `basement`), or `DEFAULT_ROOM`. A room with no file is drawn as a plain
  colour. The fight screen picks the room once in `setup()` and draws it behind everything, cropped
  to fill, under a dark shade; the combatant views, the event log and the message bar sit on
  translucent dark panels so text stays readable.
- `client/ASSETS.md`: says where the fight screen's art and backgrounds come from and how missing
  art is drawn.
- Added `tests/client/test_fight_visuals.gd` (10 tests, listed in the task file).

## Why
Task 028: the fight screen stops being text only, on the placeholder art from #81. The client still
never changes game state: views are drawn from the model built from `state`, animations only read
events, and every request ends with a full redraw from the returned state.
