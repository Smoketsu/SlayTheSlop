## What changed

- **`core/ai/`** (new): the enemy AI.
  - `move_choice.gd` picks the move. It follows a scripted pattern if the enemy has one.
    Otherwise it makes a weighted draw from `combat_ai` over the moves with weight above 0, and
    never picks the same move three times in a row.
  - `targeting.gd` picks the targets. A single-target attack hits 1 Dude, or
    `MULTI_TARGET_COUNT` Dudes at `MULTI_TARGET_PARTY_SIZE` players. An area attack hits every
    Dude. A Passed Out Dude is never a target.
  - `intents.gd` is the entry point that `fight.gd` calls. It sets the intent, records
    `move_history`, emits `intent_set`, resets enemy Guard under G30, and runs the start checks.
- **`core/combat/fight.gd`**: task 007's intent stub (`stub_intent`) is removed. Four calls go
  into `core/ai/intents.gd`, each with a comment:
  - `check_start` returns `Intents.check_start`.
  - `start_turn_in_place` calls `Intents.set_intent_in_place` for each enemy.
  - `end_player_phase_in_place` calls `Intents.begin_action_in_place` before each enemy acts (G30).
  - The file header now describes the AI instead of the stub.
- **`tests/core/ai/`** (new): 25 tests and `ai_fixtures.gd`, which holds the test-only enemies.
- **Task 007's tests, changed because the stub is gone and G30 now applies:**
  - `tests/core/combat/fixtures.gd`: the Dummy's second move, `unused`, now has weight 0. It
    was weight 1 but never chosen under the stub. With weight 0 the Dummy still always swings,
    which the existing flow tests rely on, and the change matches the move's name.
  - `tests/core/combat/test_fight_flow.gd`: `test_stub_intents` is replaced by
    `test_intents_at_fight_start`. In `test_loss`, the two-Dude part now follows whichever Dude
    the Brute aims at, because the target is now drawn. One assertion message in
    `test_solo_turn_flow` now names G30.
  - `tests/core/combat/test_fixed_seed_fight.gd`: shortened and re-recorded (see below).
- **`docs/tasks/011-enemy-intents-and-ai.md`**: status `in_review`, checks ticked, log entry.

## Why task 007's fixed-seed fight changed

`FINAL_HASH` changed for two reasons.

1. The schema commit added `move_history` and set `schema_version` to 2, so the bytes changed
   (`c13e3ba9…` to `a72c42f1…`).
2. In this commit, G30 resets the Turtle's Guard at the start of each of its actions. Before,
   the Turtle's Guard piled up (4, 8, 12, ...). Now it stays at 4, so the Turtle dies in turn 4
   instead of turn 5.

`SCRIPT` keeps its first 18 requests unchanged. The turn-5 requests were cut, and the "request
after the fight ended" check (`wrong_phase`) is now step 18. The test now expects the fight to be

and the Turtle each have one weighted move and the fight is solo, so the fight makes no
`combat_ai` draws. The change comes from G30 alone.

## Rules implemented

- **Move choice** (GDD "Enemy fields", "Enemies"; G11 answered "accept"):
  - If the definition has a `pattern`, the n-th intent of the fight is `pattern[n % size]`.
    Weights and the no-three rule do not apply, and there is no draw.
  - Otherwise there is one `Rng.weighted_index` draw on `combat_ai` over the moves with weight
    above 0, in definition order. A move chosen in each of the last 2 intents is removed before
    the draw, so the re-pick is that single draw over the remaining moves with their own weights.
  - There is no draw when only one move can be chosen.
  - A weight-0 move is never chosen at random.
- **Targeting** (GDD "Difficulty scaling", "Rules that change in co-op"):
  - A move's `target`, or its default, decides the aim.
  - `"dude"`: if there are no more standing Dudes than targets needed, every standing Dude is a
    target and there is no draw. Otherwise the targets are picked one at a time with
    `Rng.next_int` on `combat_ai`, all different, and stored in seat order.
  - `"all_dudes"`: every standing Dude.
  - `"none"`: nobody.
  - Party size counts every player, including Passed Out ones.
- **Draw order:** enemies left to right; for each enemy the move is drawn first, then the targets.
- **G30:** at the start of its own action in the enemy phase, an enemy's Guard drops to 0,
  emitting `guard_changed` only if it had Guard. This happens before it acts, and before any skip
  check that task 009 adds.
- **A target who passes out before the enemy acts** is skipped, not re-aimed. This is unchanged
  from task 007, and the choice is now documented and tested.

## Functions added

### `core/ai/move_choice.gd`

| Function | Meaning |
| --- | --- |
| `choose_in_place(state, definition, enemy) -> String` | The id of the move the enemy uses next, or `""` if it has none (no pattern and no move with weight above 0). Draws once from `combat_ai` only when there is a real choice, and then replaces `state.rng`. Does not change `enemy`. |
| `pattern_move(pattern, count) -> String` | `pattern[count % pattern.size()]`: the move for the enemy's intent number `count`, counting from 0. |
| `random_candidates(moves, history) -> Array` | The moves with weight above 0, minus `banned_move(history)`. If removing the banned move leaves nothing, the ban is lifted. |
| `banned_move(history) -> String` | The move of the last `MAX_REPEATS` intents when they are all the same move, otherwise `""`. |

### `core/ai/targeting.gd`

| Function | Meaning |
| --- | --- |
| `aim_of(move) -> String` | The move's `target` field. If it has none: `"dude"` when the move has an op that needs a target, otherwise `"none"`. |
| `single_target_count(constants, party_size) -> int` | `MULTI_TARGET_COUNT` when `party_size` is at least `MULTI_TARGET_PARTY_SIZE`, otherwise 1. Also 1 when either constant is missing. |
| `choose_in_place(constants, state, move) -> Array` | The player ids the move is aimed at, in seat order, none of them Passed Out. Draws from `combat_ai` only when there is a real choice. If the stream is missing, it takes the first standing Dudes. |

### `core/ai/intents.gd`

| Function | Meaning |
| --- | --- |
| `check_start(ruleset, state) -> String` | Why the AI cannot run a fight: a `NEEDED_CONSTANTS` entry is missing or not an int, `MULTI_TARGET_COUNT` is below 1, or the `combat_ai` stream is missing. `""` when it can. |
| `set_intent_in_place(ruleset, state, enemy, events)` | Turn flow step 1 for one enemy. Chooses the move and targets, sets `intent`, appends to `move_history` and emits `intent_set`. With no choosable move, `intent` becomes `null` and nothing is emitted. |
| `begin_action_in_place(enemy, events)` | G30: the enemy's Guard drops to 0, emitting `guard_changed` only when it had Guard. |
| `find_move(definition, move_id) -> Dictionary` | The move with that id, or `{}`. |

### `core/combat/fight.gd`

| Function | Change |
| --- | --- |
| `stub_intent(ruleset, state, enemy)` | **Removed**. It was task 007's stub. Nothing outside `tests/core/` called it. |
| `check_start`, `start_turn_in_place`, `end_player_phase_in_place` | Each now calls `core/ai/intents.gd`, as listed above. |

## Constants added (in code)

| Name | Where | Value | Meaning |
| --- | --- | --- | --- |
| `MAX_REPEATS` | `core/ai/move_choice.gd` | 2 | The most times in a row the same move may be chosen at random. The GDD's "never repeats one three times in a row" means 2. This is a GDD rule, not a tuning number, so it is not in `constants.json`. |
| `STREAM` | `core/ai/move_choice.gd` | `"combat_ai"` | The random stream for enemy move and target choice (GDD "Random streams"). |
| `SINGLE` / `ALL` / `NONE` | `core/ai/targeting.gd` | `"dude"` / `"all_dudes"` / `"none"` | The values of a move's `target` (`enemy_def.gd` `MOVE_TARGETS`). |
| `NEEDED_CONSTANTS` | `core/ai/intents.gd` | `["MULTI_TARGET_PARTY_SIZE", "MULTI_TARGET_COUNT"]` | The tuning constants the AI reads. `check_start` requires each one to be an int. |

Test-only constants and fixtures are documented in place in `tests/core/ai/`.
