# 2026-10-10: Task 018, placeholder fight screen

## What changed

- `client/fight/`: the fight screen (`fight_screen.tscn`, `fight_screen.gd`) and its pure helpers:
  `fight_model.gd` (state to display values), `targeting.gd`, `request_maker.gd`, `messages.gd`.
- `client/dev/`: `fake_gateway.gd` (a stand-in for the rules core with the same `apply()`) and
  `dev_content.gd` (placeholder content built with the real ruleset builder, and a sample fight).
- `client/ASSETS.md`: asset sources (none yet).
- `tests/client/test_fight_screen.gd`: 11 tests.
- `tests/run_tests.gd`: tests now run on the first frame, so tests can add nodes to the scene tree.

## Why

Task 018: a playable placeholder fight screen that only sends requests and animates events, so
solo uses the same path co-op will.

## Variables, fields and constants

Added (each documented in its file):
- `fight_screen.gd`: `Gateway` (the one line to swap for the real core), `animation_seconds`,
  `skip_animations`, `animation_log`, `message`, and private widget and state fields.
- `targeting.gd`: `NONE`, `ENEMY`, `DUDE`.
- `request_maker.gd`: `player_id`, `next_seq`.
- `messages.gd`: `REJECTS` (a message for every reject code), `STATUSES` (GDD status names).
- `dev_content.gd`: `CARDS`, `ENEMIES`, `DUDES` (placeholder definitions).
- `run_tests.gd`: `_started`.
- Test file: `NOT_ASSETS`.

No shared contract changed. Nothing renamed or removed.
