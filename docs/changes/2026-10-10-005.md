# 2026-10-10: Task 005, ruleset loader

Author: Agent A. Branch: `a/005-ruleset-loader`.

## What changed

- **`core/ruleset/ruleset.gd`** (new): a pure builder that turns the text of every content file
  into the read-only `ruleset` the core runs on, or returns every problem found.
- **`tests/core/ruleset/test_ruleset.gd`** (new): 19 tests. A valid in-memory set, each error
  kind, read-only-ness at every level, determinism, and one test that builds from the real
  `data/constants.json` read from disk.
- **`docs/tasks/005-ruleset-loader.md`**: status `in_review`, checks ticked, log entry.

No shared contract changed. `core/schema/` and `data/` are untouched.

## Why

The core may not read files (CLAUDE.md "The rules core is pure"), so callers read the text and pass
it in. One builder means every caller (client, tools, tests, bots) gets the same validated,
read-only content, and a broken data file fails loudly with its path instead of at runtime.

## Ruleset shape (what `build()` returns as `ruleset`)

| Key | Meaning |
| --- | --- |
| `constants` | Constant name -> its `value` from `data/constants.json` (int, float or bool). `unit` and `meaning` dropped; `_` keys skipped. |
| `cards` | Card id -> card definition (`core/schema/card_def.gd`), from `data/cards/`. |
| `enemies` | Enemy id -> enemy definition (`core/schema/enemy_def.gd`), from `data/enemies/`. |
| `dudes` | Dude id -> Dude definition (`core/schema/dude_def.gd`), from `data/dudes/`. |

Read-only at every level. Keys inserted in sorted file-path order. Empty `{}` when the build fails.

## Functions added (`core/ruleset/ruleset.gd`)

| Function | Meaning |
| --- | --- |
| `build(files) -> {ok, ruleset, errors}` | `files`: repo-relative path -> file text. `ok`: true when `errors` is empty. `ruleset`: shape above. `errors`: every problem, sorted by path, each starting with `<path>: `. |
| `freeze(value) -> value` | Makes every Dictionary and Array inside `value` read-only (Godot's `make_read_only()` is shallow). |
| `_folder_of(path)` | Internal. The known definition folder directly containing `path`, or `""`. |
| `_add_constants(text, path, constants, errors)` | Internal. Parses the constants file into `constants`. |
| `_add_definition(text, path, kind, ruleset, id_paths, errors)` | Internal. Parses, schema-checks, id-checks and adds one definition. |
| `_check_references(ruleset, id_paths, errors)` | Internal. Dude `starter_deck` and `bro_move` must name valid cards. |

## Constants added (`core/ruleset/ruleset.gd`, code constants, not tuning constants)

| Constant | Meaning |
| --- | --- |
| `CONSTANTS_PATH` | `"data/constants.json"`, the repo path of the tuning constants file. |
| `EXTENSION` | `".json"`, the extension every content file must have. |
| `KINDS` | Definition folder -> `{key, label, schema}`: ruleset key, word for error messages, schema script. Holds `data/cards/`, `data/enemies/`, `data/dudes/`. A new kind is added only once its schema exists. |
| `CONSTANT_TYPES` | `[TYPE_INT, TYPE_FLOAT, TYPE_BOOL]`, the types a tuning constant's `value` may have. |

No fields, tuning constants or schema shapes were added, renamed or removed.

## Errors reported

Invalid JSON (with the parser's line); schema failures (from each kind's `check()`); id not equal
to the file name; duplicate id (names the first file); a file outside the known folders, in a
sub-folder, or outside `data/` (so `data/gear/` fails until task 021 adds a Gear format); a file not
ending in `.json`; `data/constants.json` missing, not an object, an entry without `value`, or a
`value` that is not int/float/bool; a Dude `starter_deck` entry or `bro_move` that is not a valid
card; a non-String path or text.

## Found along the way

- Godot 4.7's JSON parser accepts trailing commas: `{"id": "x", }` parses without error.
- `json_values.parse()` reports Godot's `get_error_line()`, which is 0-based, as "line N". A
  contract question for `core/schema/`, not changed here.
- A test cannot write to a read-only Dictionary to prove it fails: the write raises an engine
  error, and the harness fails a test on any engine error. Tests use `is_read_only()` instead.
