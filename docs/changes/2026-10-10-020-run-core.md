# 2026-10-10: Task 020 run screen core (run screen, main menu, save file)

## What changed
- Added `client/run/run_screen.gd` and `client/run/run_screen.tscn`: the run screen. It holds the
  ruleset, the run state and the local player, and shows one child at a time (menu, map, fight,
  offer, run over) chosen by `screen_for()` from the state alone. Map and offer requests go through
  `send()`, fight requests through `apply()` (the run screen is the fight screen's gateway); both
  forward to the real core (`core/core.gd apply()`). It saves after every applied request outside a
  running fight and deletes the save when the run is over.
- Added `client/run/main_menu.gd` (built in code): New Run with a seed field (empty picks a seed on
  the client and shows it) through `core/run/new_run.gd start()`; Continue loads the save and shows
  the loader's error, offering New Run, when it cannot.
- Added `client/run/save_store.gd`: writes `Snapshot.to_bytes(state)` to `<path>.tmp`, then renames
  it over the save; reads it back through `Snapshot.from_bytes()`. `user://` paths only.
- `client/fight/fight_screen.gd`: new signal `state_applied(state)` after every applied request
  (once its events animated); `_redraw()` keeps the last drawing when the state has no fight (a won
  fight's last request finishes the node and clears `combat`).
- Added `tests/client/test_run_screen.gd` and `tests/client/test_save_store.gd`.

## Why
Task 020: the screens a solo floor 1 run passes through around task 018's fight screen, with saving
after every node (GDD "Sessions"). This is the routing, menu and saving half; the map and offer
screens (`map_screen.gd`, `offer_screen.gd`) are built separately against
`client/run/run_screen_api.md`.

Saving after every applied request outside a running fight is a superset of "after every node":
a finished node puts the party back on the map, and each choice inside a node is saved too.
Mid-fight states are not saved, so Continue resumes at the last node boundary or choice. A finished
run (won or lost) deletes the save, since it cannot be continued and there is no meta progression.

The main scene is still the fight screen. Making the run screen the main scene is a one-line
contract change in `project.godot`, for its own PR:
`run/main_scene="res://client/run/run_screen.tscn"`.
