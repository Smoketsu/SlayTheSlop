# 2026-10-10: Task 020, the map screen and the offer screen (Agent B)

Branch `b/020-run-choices`, built on `b/020-run-screens` (the run screen interface,
`client/run/run_screen_api.md`). The run screen, main menu and saving are a separate worker's part
of task 020 and are not in this change.

## What changed

- `client/run/map_screen.gd`: the skeleton is filled in. Draws floor 1's map from `run_state.map`:
  one button per node, placed by row (entrance at the bottom, boss at the top) and column, labelled
  with the themed node type; a line per link (walked links, and the links open now, highlighted).
  The party's node (`map.nodes[node_index]`) reads "You are here", nodes on `run_state.path` are
  dimmed, and the local player's vote (`run_state.votes`) is marked. Only the links of the party's
  node are enabled, and only while `run_phase` is "map". Picking one emits
  `{"type": "vote_node", "node_id": id}`.
- `client/run/offer_screen.gd`: the skeleton is filled in. Draws the local player's first open
  offer (`dude_state.offers[0]`): title (offer kind, or the Side Quest's name and text from the
  ruleset), the Dude's Dolla Bills, one button per option in the offer's order with the name, text,
  price and amount exactly as the state and ruleset give them, disabled when `available` is false.
  A Lift or a removal first opens a list of the option's `card_uids` (names from the Dude's cards);
  picking one sends the request with `card_uid`. Skip / Leave Baileys exists only when the offer is
  `skippable` and sends `choice_index` -1. At Baileys a Brew reads "Shake: <Brew name> — <effect>"
  (G29). With no open offer it shows "Waiting for the rest of the party to choose." in run_phase
  "node", else "Nothing to choose right now."
- `client/run/run_text.gd` (new): the player-facing words both screens use; reads only, computes
  no price, amount or chance.
- `tests/client/run_choices_drive.gd` (new, not a test file): plays a fixed-seed run (seed 1) on the
  real data, making every vote and every offer answer by pressing the screens and checking each
  emitted request equals Agent A's run bot's (`tests/run/fixtures/run_bot.gd`, read-only).
- `tests/client/test_map_screen.gd`, `tests/client/test_offer_screen.gd` (new): the tests.

## Why

Task 020 acceptance checks for the map and the node choices: the map from `run_state.map` sending
`vote_node`; reward, Tailgate, Baileys, Side Quest and Boss Gear sending task 025's `choose_reward`
(-1 only where skippable), each passing `request.gd` `check()`; prices and Dolla Bills read from the
state; every Brew at Baileys labelled Shake and no Baileys string naming a drink.
