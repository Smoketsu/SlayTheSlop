# 2026-10-10: Task 027, save/load snapshots and the state hash

Author: Agent A. Branch: `a/027-save-load-and-state-hash`. Lane: `run`.

## What changed

- **`core/run/save/snapshot.gd`** (new): turns a run state into snapshot bytes and back, and
  computes the co-op state hash (GDD "How a card gets played in co-op", step 6; GDD "Sessions",
  Saving). Pure: bytes in, bytes out. Writing them to disk or the network is the client's job.
- **`tests/run/save/test_snapshot.gd`** (new): 17 tests: round trips, hash stability and
  sensitivity, a recorded hash for a fixed state, and refusal of corrupt, foreign and invalid
  input with no engine errors.
- **`docs/tasks/027-save-load-and-state-hash.md`**: status `in_review`, checks ticked, log.

## Why

Saves after every node and co-op resync both need a state to go to bytes and back exactly
(64-bit ints included, so not JSON), to refuse bytes it cannot trust, and to have a hash that is
equal for equal states whatever order their Dictionaries were filled in.

## Functions added (`core/run/save/snapshot.gd`)

| Function | Meaning |
| --- | --- |
| `to_bytes(state) -> PackedByteArray` | `var_to_bytes(canonical(state))`, objects never allowed. Equal states give equal bytes. Does not modify `state`. |
| `from_bytes(bytes) -> {ok, state, error}` | Decodes untrusted snapshot bytes. Refuses malformed bytes or bytes that are not JSON-shaped (checked by `_scan` before `bytes_to_var` runs), a non-Dictionary, a missing, mistyped or different `schema_version` (the error names both versions), and anything `run_state.check()` reports. `state` is `null` and `error` is non-empty when refused. |
| `state_hash(state) -> String` | SHA-256 of `to_bytes(state)` (`HashingContext`), 64 lowercase hex characters. |
| `canonical(value) -> Variant` | Deep copy with every Dictionary rebuilt in sorted-key order and every Array rebuilt untyped. |
| `_refuse(error)`, `_scan(bytes, at, depth, problem)`, `_scan_string(bytes, at, problem)`, `_fits(bytes, from, size, problem)`, `_is_utf8(bytes, from, length)` | Private helpers: the refusal result, and the pre-decode walk of Godot's binary layout. |

## Constants added (`core/run/save/snapshot.gd`)

These are engine-format and safety limits, not tuning constants, so they are not in `data/constants.json`.

| Constant | Value | Meaning |
| --- | --- | --- |
| `HEADER_TYPE_MASK` | `0xFFFF` | Bits of an encoded value's header that hold the Variant type (Godot's `HEADER_TYPE_MASK`). Fixed by the engine. |
| `FLAG_64` | `1 << 16` | Header flag for an int stored in 8 bytes (Godot's `ENCODE_FLAG_64`). Fixed by the engine. |
| `COUNT_MASK` | `0x7FFFFFFF` | Bits of an Array/Dictionary count Godot reads; the top bit is ignored. Fixed by the engine. |
| `MAX_DEPTH` | `64` | Deepest Array/Dictionary nesting accepted (root is 0). Bounds recursion on crafted input. Raise it in this file if the run lane's map nests deeper. |

## Found along the way

- `bytes_to_var` logs engine errors on truncated data and invalid UTF-8, cuts a String at a NUL
  byte without saying so, and decodes an Object as `EncodedObjectAsID` even with objects
  disallowed. That is why `from_bytes` validates the whole buffer before decoding.
- `to_bytes` is canonical, so a loaded state's Dictionaries are in sorted-key insertion order. No
  result may depend on that order anyway (`core/schema/README.md`).
