# 2026-10-10: Task 029, core input checks that survive release builds

Author: Agent A. Branch: `a/029-release-safe-checks`.

## What changed

- **`core/rng/rng.gd`**: every `assert()` is gone (there were six; no other file in `core/` had
  any). Each check now runs in every build and reports through an `"error"` field. The header
  states the rule for all core code: *core functions report bad input through an error field,
  never assert or push_error*.
- **`tests/core/test_purity.gd`**: new banned pattern `\bassert\s*\(` for code under `res://core/`
  (comments and strings excluded, as for the other bans), plus the self-test
  `test_checker_bans_assert`.
- **`tests/core/rng/test_rng_bad_input.gd`** (new): 8 tests, one per kind of bad input, and one
  that valid input reports `error: ""` with the recorded seed-12345 values.
- `tests/core/rng/test_rng.gd` is unchanged; all its fixed-seed values still pass.
- `docs/tasks/029-core-input-checks-in-release-builds.md`: status `in_review`, checks ticked, log.

No shared contract changed (`core/schema/`, `data/constants.json` untouched).

## Why

GDScript removes `assert()` from release builds, so in an exported game all-zero or empty
weights reached `% 0` in `_bounded`, an unknown stream name quietly got a key, and `next_int`
accepted `hi < lo`. `push_error()` was rejected as the alternative because the caller cannot see
it and the test runner fails any test that raises an engine error. The error field mirrors how
`apply()` reports `reject` (core/schema/README.md).

## Return shapes (all additive: `"state"` and `"value"` mean what they meant before)

| Function | Success | Bad input |
| --- | --- | --- |
| `next_u64(state, key)` | `{"state": new, "value": int, "error": ""}` | `{"state": input state, "value": 0, "error": text}` |
| `next_int(state, key, lo, hi)` | `{"state": new, "value": lo..hi, "error": ""}` | `{"state": input state, "value": lo, "error": text}` |
| `weighted_index(state, key, weights)` | `{"state": new, "value": index, "error": ""}` | `{"state": input state, "value": -1 (NO_INDEX), "error": text}` |
| `shuffle(state, key, items)` | `{"state": new, "value": shuffled copy, "error": ""}` | `{"state": input state, "value": copy of items in original order, "error": text}` |
| `key_for(stream, player_id = "")` | the key (unchanged) | `""` (NO_KEY) |

On bad input `"state"` is the very object passed in, so no stream advances. `error` is
`"<function>: <problem>"`.

Bad input, per function:

- every draw: key is `NO_KEY`; the state has no `rng` Dictionary; `rng` has no such key; the
  stream's value is not an int.
- `next_int`: `hi < lo`; `hi - lo` at or above `INT64_MAX` (including a subtraction that wraps).
- `weighted_index`: empty weights; a weight that is not an int (for example a float from JSON);
  a negative weight; weights totalling 0; a total above `INT64_MAX`.
- `key_for`: a name in neither stream list; a per-player stream with no `player_id`; a shared
  stream with one.

## Constants added (in `core/rng/rng.gd`; never change them)

| Constant | Value | Meaning |
| --- | --- | --- |
| `NO_KEY` | `""` | What `key_for` returns for an unknown stream or wrong `player_id`; every draw rejects it |
| `NO_ERROR` | `""` | The `"error"` value of a successful draw |
| `NO_INDEX` | `-1` | `weighted_index`'s value on bad input. Not a valid index; GDScript reads `array[-1]` as the last item, so check `error` first |

## Functions added or changed (all static, in `core/rng/rng.gd`)

| Function | Change |
| --- | --- |
| `key_for(stream, player_id)` | Returns `NO_KEY` instead of asserting |
| `derive_stream_state(run_seed, key)` | Unchanged code; comment says any String is hashed and callers skip `NO_KEY` |
| `create_streams(run_seed, player_ids)` | Skips entries that are not a non-empty String, so it never creates a `""` key |
| `next_u64`, `next_int`, `weighted_index`, `shuffle` | Add `"error"`; check input before any draw (see tables above) |
| `shift_right_logical(x, bits)` | Now total: `bits <= 0` returns `x`, `bits >= 64` returns 0. Results for 1..63 unchanged |
| `_bounded(stream, count)` | A `count` below 1 returns `[stream, 0]` without drawing, so `% 0` cannot happen |
| `_stream_state(state, key)` | No longer asserts; call only after `_key_error` returned `""` |
| `_key_error(state, key)` (new) | Why a key cannot be drawn from, or `""` |
| `_drawn(state, key, stream_state, value)` (new) | Builds a success result |
| `_failed(state, value, error)` (new) | Builds a bad-input result with the input state unchanged |

## Found along the way

- `with_new_streams(state)` still reads `run_seed` and each Dude's `player_id` without checking;
  it expects a state that passes `RunState.check`. Not changed, because reporting an error would
  change its plain-state return shape.
- New core code (task 007 and later) must not use `assert(`; the purity lint now fails it.
